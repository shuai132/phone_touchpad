# Phone Touchpad

用手机控制 Mac 的原生触控板原型。iOS 使用 SwiftUI + UIKit，Android 使用 Kotlin + 原生 Android Views，Mac 使用 SwiftUI + Network.framework + CoreGraphics。两款手机端共用协议与轨迹验收数据，界面均为原生实现。

## 运行

需要完整 Xcode、iOS 16+ 设备与 macOS 13+。两端位于同一局域网。

1. 安装 XcodeGen，执行 `xcodegen generate`，打开生成的 `PhoneTouchpad.xcodeproj`。
2. 运行 `TouchpadReceiver`，从菜单栏授权辅助功能；如授权后无效，退出重新运行。
3. 在 Xcode 为 `PhoneTouchpad` 选择签名团队，运行到 iPhone。个人真机测试可登录普通 Apple 账号并选择 Personal Team，不要求付费会员；Xcode 自动生成开发签名，免费描述文件有效期为七天，过期需重新构建安装。
4. 在手机点“扫描 Mac 配对二维码”，扫描 Mac 菜单栏中的二维码。允许相机与本地网络权限后，会解析 Bonjour 服务并连接。
5. 无法使用相机时，可复制 Mac 配对密钥到手机，选择自动发现的 Mac，或输入 Mac 局域网 IP 连接。接收端监听 TCP 49271。

仅有 Command Line Tools 时，可执行 `Scripts/build-mac.sh` 构建本机架构的 Mac 应用，产物为 `.build/manual/TouchpadReceiver.app`。临时签名仅用于本地开发，正式分发仍需开发者签名和公证。

Mac 本地反复更新时，建议使用已有开发证书签名：通过 `TOUCHPAD_SIGN_IDENTITY` 为 `Scripts/build-mac.sh` 显式选择证书名称或指纹。脚本在被忽略的 `.build/manual/signing-identity` 中记住选择，后续沿用；尚未选择证书时才回退到临时签名。证书失效时构建会失败，不会静默改用临时签名。临时签名重编译、改签名或更换应用副本后，辅助功能旧授权可能失效；即使开关显示开启，也应以当前应用内的授权状态为准，并在系统设置重新授权后重启、重新扫码。不要关闭系统安全保护来绕过该检查。

## Android

需要 JDK 17+ 和 Android SDK 34。可在 Android Studio 打开 `android` 目录，或设置 `JAVA_HOME`、`ANDROID_HOME` 后执行 `Scripts/build-android.sh`。项目包含校验发行包 SHA-256 的 Gradle 8.9 Wrapper。

调试 APK 位于 `android/app/build/outputs/apk/debug/app-debug.apk`，声明支持 Android 8.0+。这是调试签名构建，已通过 Android 14 隔离模拟器安装与仪器测试，尚未完成真机验收。首次连接同样需要运行 Mac 接收端并授权辅助功能。

Android 实现了二维码扫描、NSD 自动发现、手动连接、与 iOS 对应的手势引擎、设置、触觉反馈、心跳和后台断开。扫描与触摸处理接入原生 Activity/View，读取 MotionEvent 历史样本；Android 14+ 使用纳秒采样时间。扫码、NSD 跨设备发现、实际触感与真实设备生命周期仍需真机测试。

Kotlin 核心对照 `Tests/Fixtures/gestures.json` 中由 Swift 引擎生成的 37 组轨迹，核对动作、坐标增量、手指数、采样时间和协议版本。`Scripts/check-gesture-fixtures.sh` 防止 Swift 实现变化后夹具未同步。

`Scripts/check-android-interop.sh` 使用真实 Swift 接收端和 Android 应用所用的同一 Kotlin 传输/会话代码，在 JVM 上验证 TLS-PSK 配对、心跳、错误密钥、版本拒绝、已有会话保护，以及服务器断开后的客户端清理。Mac 输出只记录在内存，不操作桌面。该检查已通过，但不等同于 Android 设备上的网络或 UI 验收。普通 `:core:test` 没有运行中的接收端时会跳过此项实时互通测试。

`Scripts/check-android-device.sh` 在独立临时 Android 14 模拟器上安装调试包，运行三项仪器测试：设置保存、原生 MotionEvent 历史样本与交错抬指/取消，以及真实应用连接到 Swift 接收端。网络测试覆盖横屏保持连接、双指缩放/旋转/滚动、三指拖移，以及后台断开释放。Mac 端只记录 CGEvent，不投递到桌面；检查原生旋转和缩放结束、拖动释放及连接清理。脚本仅操作自行创建的模拟器，结束后删除其数据，截图与测试日志保存在 `.build/android-device/`。需要 SDK 中已安装本机架构的 API 34 Google APIs 系统映像，且本机 TCP 49271 端口空闲。模拟器验收不代表真实无线网络、相机、触感或目标应用兼容性已通过。

## 原型行为

- 单指移动、轻点左键、双指轻点右键；连续轻点带系统双击/多击计数。
- 双指像素滚动，包含滚动阶段和速度衰减惯性；新触摸停止惯性。
- 实验性原生双指捏合与旋转，可同时发生；双指双击发送智能缩放。启用后双指单击右键延迟约 280 ms，以区分双击。
- 支持按压点击第一段：真实压感设备达到门槛时按下左键，减压或抬指释放；按住移动可拖移，连续按压保留系统双击计数。没有压力数据时可选约 0.35 秒的长按模拟，默认关闭。
- 可选轻点拖移：轻点后在附近再次按住或移动，抬指释放；快速第二次轻点保持双击。可关闭轻点并使用左右键按钮。
- 可选三指拖移，抬起任一手指释放；默认三指或四指滑动发送 Control + 方向键，依赖 Mac 系统快捷键设置。
- 配对失败显示 Mac 忙、辅助功能未授权、版本不兼容等具体原因；第二个客户端不能抢占现有连接。
- Bonjour 自动发现、二维码配对和手动地址连接；连接后采用独立触控区域，设置在单独页面中调整，打开设置会释放当前手势。
- Mac 菜单栏保存指针速度、加速、自然滚动及独立的双指滚动/捏合缩放灵敏度设置；指针与滚动使用手机采样时间计算速度。连续移动以累计目标坐标投递，避免系统事件队列尚未处理上一样本时丢失位移；新触摸重新以系统指针位置为起点。
- iOS 适配层重放 UIKit 提供的合并触摸样本，多指以共同时间插值对齐；没有合并样本时使用当前事件快照。零位移/重复样本不再清空甩动速度，三指拖移保留启动阈值前的累计位移。
- 双端心跳；失去响应约 5 秒后断开并释放拖动，手机显示往返延迟。
- 断开、退到后台或触摸取消时释放拖动；只允许一个已配对控制端。iOS 触控区域尺寸变化时也会取消当前手势，避免跨布局坐标混用；此布局回调尚需 iPhone 旋转屏幕验收。
- Mac 锁屏/休眠通知会断开现有连接；正常退出时关闭监听器并释放拖动、原生变换和滚动状态。
- 滚动中断时发送取消阶段；没有进入惯性时不会发送孤立的惯性结束事件。

## 实验性原生变换手势

`Mac/NativeGestures.swift` 单独封装未公开的 CGEvent 手势编码，生成 AppKit 的 magnify、rotate 和 smartMagnify 事件，包含开始、变化、结束与取消阶段。这些值依据 Apple WebKit 的 [CoreGraphics 测试 SPI](https://github.com/WebKit/WebKit/blob/main/Tools/TestRunnerShared/spi/CoreGraphicsTestSPI.h) 和 [IOKit SPI](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/PAL/pal/spi/mac/IOKitSPIMac.h) 中的接口定义；没有用键盘快捷键替代缩放或旋转。

Mac 启动时做 AppKit 事件读回检查，配对时通知手机是否支持。检查失败时不启用变换手势。未公开编码可能随系统升级改变，不能保证所有 macOS 版本或应用兼容；正式分发前需评估接口稳定性与分发要求。

双指识别按距离、夹角和共同平移区分变换与滚动。手指 ID 决定向量顺序，处理角度跨越 ±π 的情况，并在指头加入/抬起时结束对应手势。取消或断连时发送取消阶段。

## 传输路线决定（2026-10-31）

先使用 Wi-Fi 局域网中的 TCP + TLS 长连接，完成 iPhone 真机测试，测量输入延迟、抖动和稳定性。不能将局域网连接视为零延迟，也不能在没有测量依据时将延迟归因于 JSON 或加密。

`Shared/ConnectionRoute.swift` 提供局域网地址与已有 TCP 转发端点两个连接入口，iOS 会话层统一复用 TLS、配对、心跳和消息处理。转发端点需要另行建立，不会自动创建 USB 隧道。连接层继续向可替换接口演进，将连接建立与消息编码、会话管理、输入处理分开。如果真机结果表明无线抖动影响体验，再接入 USB 隧道，复用现有 TCP、配对加密、应用消息协议和输入处理。USB 是后续连接方式，目前尚未实现；支持 TCP 不代表已经支持 USB。

连接方式与输入后端独立：现有事件注入模式和计划中的虚拟触控板模式共用传输基础设施。虚拟触控板能否接入系统原生多指识别仍需验证，不能将规划视为已支持。当前继续使用 JSON；保留编码替换边界，待性能测量证明必要后再评估 FlatBuffers 等二进制格式。

## 加密连接

Mac/iOS 使用系统 Network.framework，Android 使用 [Bouncy Castle 轻量 TLS API](https://www.bouncycastle.org/documentation/documentation-java/)；连接均为 TLS 1.2 PSK，套件为 `TLS_PSK_WITH_AES_128_GCM_SHA256`，两端在应用数据交换前验证实际协商的版本和套件。随机 256 位密钥通过二维码或手动复制传递，不再使用六位数字密码，也不在应用消息中传输密钥。旧版明文客户端以及不带应用协议版本字段的早期原型均不兼容，需要同时更新手机与 Mac 两端。

二维码本身包含连接密钥，请勿公开分享。Mac 重启或点击“断开并更换密钥”会使旧密钥失效。密钥暂不持久保存，没有自动重连与设备信任管理。

当前 PSK 套件不提供前向保密。后续正式版本仍需评估 TLS 1.3 证书身份、密钥生命周期、配对尝试限流和 Android 真机兼容性。接收端限制最多四个待处理连接，未配对连接约 10 秒超时；这不是完整的防拒绝服务机制。

系统 API 依据：[Apple TLS 安全选项](https://developer.apple.com/documentation/network/security-options)、[向 Network.framework 迁移的技术说明](https://developer.apple.com/documentation/technotes/tn3213-moving-from-multipeer-connectivity-to-network-framework)。

## 按压力度与硬件限制

在手机设置的“按压与拖移”中，iOS 会显示当前是否提供真实手指压感。仅在系统报告 `forceTouchCapability` 可用时读取 `UITouch.force / maximumPossibleForce`，包括合并样本中的压力峰值；不把触摸面积或 Haptic Touch 持续时间当成真实力度。默认启用真实压力点击，硬件不支持时此项不可用，可自行开启“长按模拟按压”。长按停留约 0.35 秒后按下左键，移动拖移，抬指释放；正常移动不会因持续时间较长自动变成按下。

Android 默认关闭“压力变化点击”。用户可选择实验性压力变化估计，按同一次触摸的起始压力计算相对增幅，并参考系统 `DEEP_PRESS` 分类；该分类和 `MotionEvent.pressure` 都不保证来自测力硬件。常见的恒定 1.0 值不会被当成重按。压力估计与长按模拟是二选一；机型无法提供可靠变化时应使用长按模拟，不能称为真实压感。

两端按下/释放采用滞回，减压时先保留最后一段拖移再释放，抬指事件不会用残留压力重新按下；加指、取消、后台和断连也会释放。按下与轻点采用不同触觉反馈。此功能是普通鼠标点击/按住的第一段，尚未注入第二段 Force Click 的原生压力事件，也不宣称已经实现查词、预览或等效触觉硬件。

依据：[UIKit 压力值](https://developer.apple.com/documentation/uikit/uitouch/force)、[UIKit 压力能力](https://developer.apple.com/documentation/uikit/uiforcetouchcapability)、[Android MotionEvent](https://developer.android.com/reference/android/view/MotionEvent)、[Apple Force Click 说明](https://support.apple.com/102309)。当前真实压力硬件路径已完成逻辑测试与原生适配编译，但没有在支持手指真实压感的手机上验收；Android 原生 MotionEvent 测试使用模拟器构造压力，不是测力传感器实测。

## 与 Apple 触控板的差距

尚未实现手掌抑制和设备记忆；Android 客户端已有调试构建并通过模拟器联调，但真机验收未完成。原生捏合/旋转和智能缩放已接入实验性路径，但尚未完成手机到目标应用的真机验收。指针加速、滚动惯性、三指拖移和多击计数需要真机调校；当前不能称为完整 Magic Trackpad 复刻。

手机与 Magic Trackpad 的尺寸、压力传感器和触觉硬件不同，Force Touch 不能承诺等效复刻。指针与滚动使用公开 CoreGraphics 接口；空间切换仍是快捷键映射，不等同于连续交互式系统手势。

## 验证

执行 `Scripts/check.sh`：

- TCP 分包、粘包、超长与非法帧检查。
- 手指数变化避免误点击/误移动、三指拖移释放、单次滑动只触发一次动作。
- 轻点拖移的移动/按住触发、双击保留、抬指/加指释放、超时/距离限制和取消清理；不将单指偏移误判为多指滑动。
- 惯性衰减、停留后不产生惯性、指针加速与线性比例、非法输入和速度重置。
- 合并样本的曲线路径、跨手指时间对齐、重复/过时/无效样本处理、抬指重复样本保留惯性，以及慢速三指拖移的位移守恒。这些采样检查使用构造轨迹，不替代 UIKit 真机事件与延迟测试。
- 捏合增量比例、同时旋转、角度跨界、滚动互斥、手势取消和双指双击/右键区分；AppKit 事件类型、数值与各阶段读回。
- 密钥与二维码载荷解析、格式/版本拒绝和特殊字符往返；实际生成的二维码经 CoreImage 解码后与原始载荷一致。
- 使用真实客户端及本机 TLS 测试对端，检查配对、协商套件、错误密钥无法配对、明文帧不被接收、心跳与失联断开。使用回环地址并关闭自动发现，不请求辅助功能权限。
- Mac 源码、客户端网络代码类型检查，以及 iOS 界面语法检查。
- 连续输入在系统指针尚未更新时仍累计全部位移，点击沿用最新目标坐标，重置后新触摸重新锚定。该回归使用不投递系统的事件记录器。
- 两个真实客户端竞争同一接收端时保留原会话；拒绝后可重连、版本/未配对输入拒绝、断开不覆盖拒绝原因。权限拒绝检查注入授权结果并记录事件，不修改系统权限。

本机独立检查、Mac 完整编译和临时签名已通过。安装 Xcode 后，iOS 模拟器与真机目标的 Debug 完整构建均已通过（关闭代码签名）；此前仅语法检查的限制已解除。使用免费 Personal Team 签名后，应用已安装到连接的 iPhone；签名校验通过且描述文件包含该设备。首次启动被系统信任检查拦截，尚待手机信任开发者后继续联调，不能据此认定真机触摸与延迟已验证。

仍需真机签名安装、真实相机扫码、Bonjour 跨设备发现，以及真机验证辅助功能授权、真实目标应用中的输入注入/释放、跨屏指针、滚动方向和延迟。未进行端到端触控体验验收。

应用协议是 TLS 内的逐行 JSON，字段为 `kind`、`x`、`y`、`fingers`、必需的应用协议版本 `version`、可选采样时间 `time`、配对回复中的可选能力标志 `nativeGestures` 和拒绝回复中的 `rejection`，定义于 `Shared/Protocol.swift`。二维码载荷包含协议版本、Bonjour 服务名及配对密钥，定义于 `Shared/PairingInvitation.swift`。

可单独执行 `Scripts/check-receiver.sh` 运行真实手势引擎、客户端、TLS 和接收端的完整逻辑链路，将 CGEvent 记录在内存中而不投递到桌面。它验证原生缩放输出、实际惯性计时、多击计数、断连释放拖动、会话断开保留监听器、活连接停止心跳后释放鼠标/滚动/原生变换，以及关闭监听器。本机已通过。因使用生产配对权限检查，调用进程需要已有辅助功能权限；脚本不会申请权限。

`Scripts/check-native-delivery.sh` 只检查原生手势到专用 GUI 窗口；已在 macOS 27.0.1（26A434）通过跨进程 AppKit 回调、阶段和 NSScrollView 从 1.0 放大到 1.125 的检查，手动解锁后重新回归通过。`Scripts/check-input-chain.sh` 新增完整的真实窗口链路，包括点击、拖动、滚动及超时释放。两者都会打开测试窗口并短暂移动、恢复指针，需桌面已解锁且调用进程已有辅助功能权限。

手动解锁后，`Scripts/check-input-chain.sh` 已在本机真实 AppKit 测试窗口通过：缩放、旋转、智能缩放、滚动及惯性、新触摸停止惯性、双击计数、右键、三指拖移、TCP 断连释放，以及存活但停止发送数据的 TLS 连接超时后释放鼠标并取消滚动。失联测试使用非零滚动位移。运行中窗口失焦会中止测试；此前出现过失焦、右键未到达及零位移滚动取消未记录的失败，改为非零位移后完整重跑通过，仍需真机重复测试排查稳定性。该结果证明构造轨迹经真实客户端、TLS 和接收端到专用窗口的输入链路，不代表 UIKit 触摸、无线网络或任意目标应用兼容性已验收。锁屏/休眠通知到生命周期清理的接线已经类型检查，尚需实际系统状态切换验证。

当前应用协议版本为 1。Mac 在接收任何输入前检查版本及配对状态，拒绝回复使用 `kind: rejected` 与稳定的原因代码，iOS 与 Android 原生端均使用该协议。

Android 构建、37 组跨语言轨迹检查和 JVM 到 Mac 的加密互通检查已通过，Android Lint 无错误。仍有国际化、原生 API 兼容分支等警告，以及 Bouncy Castle JAR 中未使用的 JSSE 信任管理器代码触发的静态警告；本客户端只启用 PSK 套件并验证协商版本/套件，不创建 X.509 信任管理器。Android 14 模拟器 UI 与网络联调已通过，真实相机和手机仍待验收。

## 本机延迟基线

执行 `Scripts/check-latency.sh`，分别测量 JSON 编码/解码，以及真实 iOS 会话代码通过本机 TLS 连接到真实 Mac 接收端构造 CGEvent 的耗时。事件仅记录在内存，不投递桌面；测试按约 120 Hz 发送并丢弃预热样本，报告中位数、p95 和 p99。测试临时跳过权限门禁仅用于内存记录，不修改系统权限。

本次优化构建的本机样本：JSON 编码 p50 约 0.0025 ms、解码 p50 约 0.0032 ms；本机 TLS 到事件记录 p50 约 0.230 ms、p95 约 0.604 ms、p99 约 1.224 ms。数值随设备负载变化。这不是手机触摸到显示的延迟，不包含 Wi-Fi、USB、真实事件投递和屏幕刷新，不能据此声称真机延迟达标。

## 真机多指问题诊断

iOS Debug 构建会在应用缓存的 `input-diagnostics.json` 中保存最近一次触摸摘要：最大手指数、样本帧数、持续时间、识别动作计数、手势选项及结束/取消原因。仅保存本地摘要，不含触点坐标、配对密钥或主机名；Release 构建不启用。Mac 面板显示最近收到的多指操作，帮助区分手机识别、网络接收与目标应用响应。新增诊断不等于多指问题已修复，仍需复现用户实际动作。

`Scripts/check-web-pinch.sh` 使用本机静态页面和真实 WKWebView，通过手势引擎、实际客户端、TLS 和接收端投递双指捏合。本机已验证网页视图从 1.0 放大到约 1.5，并收到结束阶段。脚本会打开测试窗口并暂时移动、恢复指针，需要已有辅助功能权限；该结果不代表 iPhone 触摸识别、Safari/Chrome 等所有应用或四指系统手势已经通过。

`Scripts/check-virtual-hid.sh` 是 macOS 26+ 的独立可行性探测，用标准鼠标描述符检查当前签名环境能否构造 CoreHID 虚拟设备。它不会激活设备或发送输入报告，不冒充苹果硬件。本机当前签名环境下构造返回不可用；这是虚拟设备路线的一道未通过条件，不能将另一种事件注入模式标成虚拟触控板已可用，也不能据此单独证明多指报告格式是否兼容。

## 双指灵敏度

在 Mac 菜单栏接收端向下滚动，可分别调整“双指滚动灵敏度”（20%–300%，默认 100%）和“捏合缩放灵敏度”（10%–150%，默认 35%）。设置保存在 Mac，本次连接的 iOS/Android 手机均适用，重启保留；“还原手势灵敏度”恢复这两个默认值。手机无需升级即可获得接收端的新增益。

滚动位移和惯性使用同一增益；调整灵敏度时先结束已有惯性，避免旧速度继续运行。捏合按对数比例缩放，再转换回原生 magnification 增量，因此相同手势拆成不同数量样本时仍得到相同倍率，放大/缩小互逆。指针速度、旋转及三指切换不受这两个设置影响。

`Scripts/SensitivityCheck.swift` 通过真实客户端、TLS 和接收端的事件记录验证滚动/缩放增益、降低后的默认值、采样拆分等价性、反向缩放及设置恢复，并验证调整滚动增益会停止旧惯性；由 `Scripts/check.sh` 一并执行。
